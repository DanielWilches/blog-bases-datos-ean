Modelo Relacional

¿Qué características tiene una base de datos relacional?

Publicado: Febrero 2026 Lectura estimada: 8 min Área: Modelado & Diseño Lógico de Datos

El modelo de base de datos relacional fue formulado en 1970 por el matemático e investigador británico de IBM, Edgar Frank Codd, en su histórico artículo "A Relational Model of Data for Large Shared Data Banks" (Codd, 1970). Esta innovación representó una auténtica revolución paradigmática en la informática al separar limpiamente la representación lógica de los datos de su implementación física en disco.

1. Fundamentos Matemáticos y Terminología Formal

Una base de datos relacional se fundamenta rigurosamente en la teoría de conjuntos y en la lógica de predicados de primer orden. Aunque en el lenguaje cotidiano de la industria se habla de tablas, filas y columnas, la literatura técnica formal define:

Término Formal (Codd) Término Estándar SQL Definición Matemática / Conceptual
Relación Tabla Subconjunto del producto cartesiano de una lista de dominios D1 × D2 × ... × Dn.
Tupla Fila / Registro Elemento individual de una relación. Representa una instancia concreta o aserción lógica del mundo real.
Atributo Columna / Campo Propiedad nombrada que describe el papel de un dominio dentro de la relación.
Dominio Tipo de dato / Restricción Conjunto de valores atómicos permitidos para un atributo (ej. enteros positivos, cadenas alfanuméricas).
Grado Número de columnas Cantidad total de atributos que componen el esquema de la relación.
Cardinalidad Número de filas Cantidad actual de tuplas almacenadas en la relación. Varía dinámicamente con las operaciones DML.

2. Reglas y Restricciones de Integridad

La confiabilidad de un sistema relacional descansa en el cumplimiento ineludible de tres niveles de integridad:

  • Integridad de Entidad: Toda tabla debe tener una Clave Primaria (Primary Key - PK) cuyos valores sean únicos y no nulos (NOT NULL). Esto garantiza que ninguna tupla sea idéntica a otra y que cada registro sea inequívocamente localizable.
  • Integridad Referencial: Las relaciones entre tablas se establecen mediante Claves Foráneas (Foreign Keys - FK). La regla exige que si una tupla en una tabla hija hace referencia a un valor en una tabla padre, dicho valor debe existir efectivamente en la clave primaria del padre o, de lo contrario, ser nulo (Date, 2019). Esto previene la existencia de registros huérfanos.
  • Integridad de Dominio: Los valores de una columna deben pertenecer estrictamente a su dominio asignado mediante tipos de datos nativos, valores por defecto (DEFAULT) y restricciones de validación condicional (CHECK).
SQL DDL - Ejemplo de Integridad 
-- Ejemplo de definición rigurosa de integridad relacional
CREATE TABLE departamentos (
    id_departamento INT PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL UNIQUE
);

CREATE TABLE empleados (
    id_empleado INT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    salario DECIMAL(10, 2) NOT NULL CHECK (salario > 0),
    id_departamento INT NOT NULL,
    -- Integridad referencial con eliminación en cascada restringida
    CONSTRAINT fk_empleados_departamento 
        FOREIGN KEY (id_departamento) 
        REFERENCES departamentos(id_departamento)
        ON UPDATE CASCADE 
        ON DELETE RESTRICT
);

3. El Estándar Transaccional ACID

El rasgo distintivo indiscutible de los motores relacionales es su garantía de transaccionalidad mediante el modelo ACID, introducido por Jim Gray (Gray, 1981):

Las 4 Garantías Fundamentales de ACID
  • Atomicidad (Atomicity): Principio del "todo o nada". Si una transacción bancaria debita $1,000,000 de la cuenta origen y el sistema colapsa antes de acreditarlos a la cuenta destino, el motor hace ROLLBACK automático y no aplica ningún cambio.
  • Consistencia (Consistency): Una transacción solo puede transformar la base de datos de un estado válido a otro estado igualmente válido, respetando todas las reglas de integridad, disparadores (triggers) y restricciones lógicas.
  • Aislamiento (Isolation): Las transacciones concurrentes se ejecutan sin interferir entre sí. Aunque ocurran miles por segundo, el resultado debe ser equivalente a haberlas ejecutado una después de otra de forma serial.
  • Durabilidad (Durability): Una vez que una transacción ha recibido confirmación de COMMIT, sus efectos son permanentes y no se perderán incluso si sobreviene una caída de tensión catastrófica inmediatamente después.

Niveles de Aislamiento ANSI SQL y Fenómenos Concurrentes

Para equilibrar la velocidad de procesamiento con la pureza del aislamiento, el estándar SQL define cuatro niveles progresivos:

Nivel de Aislamiento Lectura Sucia (Dirty Read) Lectura No Repetible (Non-repeatable Read) Lectura Fantasma (Phantom Read)
Read Uncommitted Permitida ⚠️ Permitida ⚠️ Permitida ⚠️
Read Committed (Default en Postgres) Prevenida ✅ Permitida ⚠️ Permitida ⚠️
Repeatable Read (Default en MySQL) Prevenida ✅ Prevenida ✅ Permitida / Mitigada ✅
Serializable (Máxima rigidez) Prevenida ✅ Prevenida ✅ Prevenida ✅
Conclusión

Las bases de datos relacionales continúan siendo el estándar de oro en sistemas donde la integridad formal, la ausencia de ambigüedad y la consistencia inmediata son imperativas, tales como la contabilidad, la banca, la facturación electrónica y los sistemas de gestión empresarial (ERP / CRM).
