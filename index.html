Arquitectura SGBD

1. ¿Qué es un motor de bases de datos?

Análisis de los componentes internos de un DBMS: motor de almacenamiento (Storage Engine), optimizador de consultas, planificador de ejecución y gestor de buffers.

Modelo Relacional

2. ¿Qué características tiene una base de datos relacional?

El modelo matemático de E.F. Codd: tuplas, atributos, claves primarias, llaves foráneas y el cumplimiento estricto del estándar transaccional ACID.

Lectura: 7 min Explorar artículo →
Paradigma NoSQL

3. ¿Qué es una base de datos no relacional?

Orígenes del movimiento NoSQL, flexibilidad de esquema, el Teorema CAP de Eric Brewer, la filosofía de consistencia eventual BASE y escalado horizontal.

Lectura: 6 min Explorar artículo →
Ecosistema NoSQL

4. ¿Cuáles bases de datos no relacionales se manejan en la actualidad?

Taxonomía completa: Documentales (MongoDB), Clave-Valor (Redis), Columnar (Cassandra), Grafos (Neo4j) y la nueva frontera de Bases Vectoriales (Pinecone, Qdrant).

Comercial / Enterprise

5. ¿Cuáles son los motores relacionales licenciados más utilizados?

Revisión profunda de Oracle Database, Microsoft SQL Server, IBM Db2 y SAP HANA. Métricas de licenciamiento, alta disponibilidad y escenarios de misión crítica.

Lectura: 8 min Explorar artículo →
Código Abierto

6. ¿Cuáles son los motores relacionales Open Source?

PostgreSQL (el motor relacional de objetos más avanzado), MySQL, MariaDB y SQLite. Tipos de licencias libres (GPL vs BSD), ecosistema y rendimiento comparativo.

Lectura: 7 min Explorar artículo →
Diseño Lógico

7. ¿Qué es la normalización de base de datos?

Objetivos y beneficios del proceso de normalización: prevención de anomalías de inserción, actualización y borrado, reducción de redundancia y dependencias funcionales.

Algoritmos de Diseño

8. ¿Qué formas normales existen? (1FN a 5FN / BCNF)

Desarrollo riguroso de cada forma normal con un caso práctico paso a paso (Facturación comercial) y el momento estratégico para aplicar desnormalización en entornos analíticos.

Ciberseguridad

9. ¿Qué criterios tener en cuenta para estrategias de seguridad?

Pilares defensivos: Control de acceso RBAC, cifrado TDE y TLS 1.3, auditoría, prevención contra SQL Injection, políticas de backup (RPO/RTO) y cumplimiento legal (Habeas Data / GDPR).
